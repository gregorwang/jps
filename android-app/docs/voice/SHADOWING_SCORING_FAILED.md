# 失败记录：用 Gemini 做跟读逐拍打分（2026-10-02，不做）

结论先写在前面：**免费层 Gemini 做不了「哪一拍错了、长音 / 促音漏没漏」的跟读打分。** 用户决定这个功能不做。以后有人再提「让 Gemini 听录音打分」，先看这份记录。

## 想做什么

现在的发音评分（`japanese-pronunciation-api`，Nova-3 识别 → 可选 Whisper 复核 → 按文字对齐音拍）有个先天缺陷：识别模型会把发音「纠正」成合法的词，读成「おばさん」也可能被识别成「おばあさん」，所以**长音缩短、漏促音这类错误根本看不到**。

设想是让 Gemini 直接听录音，逐拍指出错在哪。

## 限制条件

- key 是 Google AI Studio **免费层**。用户实测 Flash 每分钟最多约 1 次，Flash-Lite 每分钟约 20 次。跟读是一句一句地录，只有 **Flash-Lite** 用得起。
- Flash 系列（3.5 / 3.6 / 3.8）在免费层经常 503（high demand），Flash-Lite 偶尔 500。

## 怎么测的

- 调用方式：原生 `generateContent`，音频放 `inline_data`（`audio/mp3`、`audio/mp4`），`thinkingLevel: low`，`responseMimeType: application/json`。
- 素材：
  - Edge TTS 合成 6 段，每句一对（读对 / 故意读错）：
    - ちょっとまってください / ちょとまてください（漏 2 个促音）
    - おばあさん / おばさん（长音缩短）
    - ほんとうに / ほんとに（长音缩短）
  - 用户真人录音 2 段（在 `photo/`，不进仓库）：
    - Test1「やばい…これは本気でやばい」，全部读对。
    - Test2「抵抗しないでくれたら」，最后的「たら」故意读错。
- 每段问 2–3 次，看结果稳不稳定。

## 三种问法的结果

### 1. 把目标句一起给它，让它对比
它会往目标句上靠（脑补），读错了也判成「没问题」。**不可用。**

### 2. 盲听写：不给目标句，只让它逐拍写出听到的假名
- **合成音（Flash-Lite）**：6 段对了 5 段，抓到了「おばさん」和「ほんとに」。漏促音的「ちょとまて」所有模型都没听出来，可能是 TTS 本身读得不像漏了。
- **真人录音（Flash-Lite）**：
  - **冤枉读对的地方**：「本気」3 次都写成「じゅんき」，「抵抗」3 次都写成「ていこく」，这两处用户其实都读对了。
  - 「たら」读错的地方能察觉到不对，但每次写出来的都不一样。
- **真人录音（3.6 Flash）**：「ほんき」3 次都对，「てーこー」也对，但 Test2 的结尾每次结果都不同。它准一些，可是每分钟只能调 1 次，还经常 503。

### 3. 选择题：程序列出几种读法（标准读法 + 常见错读），让它选
| 录音 | 正确答案 | Flash-Lite 选的 |
|---|---|---|
| ちょっとまってください（读对） | A | A（另一次 500） |
| ちょとまてください（漏促音） | D | A、A ✗ |
| おばあさん（读对） | A | A、A |
| おばさん（长音缩短） | B | A、A ✗ |
| ほんとうに（读对） | A | A、A |
| ほんとに（长音缩短） | B | B、B ✓ |
| Test1（读对） | A | A（另一次 500） |
| Test2（たら 读错） | 都不对 | A、A ✗ |

它几乎只选 A（也就是标准读法）。4 段读错的录音只认出 1 段，故意读错的「たら」也判成了正确。**比盲听写还差。**

## 为什么不行

- 音频大模型和 ASR 一样，是被训练来「听懂说的是哪个词」的，天生会把发音往合法词上归一，这正是跟读打分要抓的那一类错误。
- 只要给它任何提示（目标句、选项），它就往标准答案上靠；什么都不给，它又会在真人录音上听错（じゅんき、ていこく）。两头都不可靠，冤枉人比漏判更伤学习体验。
- 能听准一些的只有更大的模型，在免费层用不起。

## 以后如果要重新考虑

满足下面任意一条再说，否则别再花时间测：
- 有了付费 key，可以稳定调用 Flash 或更强的模型，并且实测真人录音没有误判。
- **不靠 AI 的做法**：长音、促音本质上是**时长**问题（おばあさん 的「ばあ」大约是 おばさん 的「ば」的两倍长）。可以把用户录音和原声 / TTS 按音频特征（MFCC）做 DTW 对齐，直接量每一拍是长了还是短了。不花调用次数，结果稳定，但要在发音 API 里写一段信号处理，工作量不小。用户这次没选。
- 比较时注意 えい = ええ、おう = おお 要当成同一个读法，否则会出现假报错。

## 测试脚本

临时脚本只放在会话 scratchpad 里（里面有 key，**不进仓库**）。要重测的话，照上面「怎么测的」重写一遍即可：一个音频文件 + 一段提示词，直接调 `generateContent`。
