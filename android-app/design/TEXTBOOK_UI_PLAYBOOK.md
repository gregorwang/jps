# 教科書的界面设计：画画布之前读这一份

新文档做成自習教科書时，**先在画布上设计这本书的界面，用户点头再写数据和代码**。这一份是几轮被否、被认可之后总结出来的做法。画画布之前从头读完；画完对照第 5 节的清单自查一遍，再拿给用户看。

---

## 1. 我们在做什么

做的是 **UI 设计、视觉引导**，不是给知识点配插图。一屏界面要做到三件事：

1. **把眼睛引到关键的那一处**：一屏只有一个焦点，用户一眼就知道该看哪、该点哪。
2. **让人参与进去**：知识点要靠用户自己动手（点、选、对照）才显出来，而不是读一段图解。
3. **把知识点串起来**：各课是同一个装置的不同用法，学到后面能看出前面几课在讲同一件事。

做到了这三件，画面自然就是「新的视觉语言」；做不到，画得再漂亮也只是插图。

## 2. 两次被否、两次被认可

| 书 | 被否的版本 | 用户的原话 | 被认可的版本 |
|---|---|---|---|
| 第十三巻 笑い | 照现有代码把 7 种题型描了一遍，再贴便签挑毛病 | 「没动脑子」：没有让人聚焦、记得住的东西 | **一根线**：直线是常理，偏出去是ボケ，折回来是ツッコミ，笑落在折点。每种题型的揭晓画面把这个结构画出来 |
| 第十四巻 涙 | 把上一本的「一根线」换个方向接着用（线断开 + 空圈） | 「为什么非得用线」「我们做的是 UI 设计、视觉引导」「不要老是偷懒」 | **平时 / 这一刻**：后面一张「平时」底片卡，前面一张「这一刻」实卡，题目只问「哪里不一样？」，点出的那一块亮起来，连回底片，次数显示「×15 → ×1」 |

被否的两版有一个共同点：**都没想这本书本身**。第一次照搬现有代码，第二次照搬上一本被认可的图形。

被认可之后用户补了一句，这句同样重要：

> 以前的经验只是参考。线、曲线、阶梯不是不能用，要用到恰当的地方，不能完全照抄。

第十四巻里「称呼一次跳三级」用了台阶加曲线，用户点名说用得好，因为称呼本来就是一级一级的台阶。

## 3. 做法（按顺序）

### 3.1 从头读完原文，再找这本书的「共同结构」

- 不要从目录下结论（第十三巻系列的教训：后篇回收前篇是承上启下，不是重复）。
- 把文档里所有手法放在一起看，问：**它们其实是同一件事的哪几种变化？** 用一句话说出来：
  - 笑い：「制造偏离，再点破它」→ 一根线偏出去、折回来。
  - 涙：「这一刻和平时不一样」→ 两层卡对照。
- 这句话说不出来，说明还没想清楚，**先别画**。

### 3.2 把共同结构做成一个「装置」，而不是一张图

装置的标准：

- **有固定的位置关系**，用户第二次看到就知道怎么读（底片永远在后面、错开一点；实卡永远在前面）。
- **题目从装置里自然长出来**。涙 的题目永远是「哪里不一样？」，用户点的就是装置里亮起来的那一块。
- **揭晓是装置的变化，不是多出一段文字**：那块亮起、连线、次数对比。讲解文字只补一两句。
- **最后一课把装置叠起来**，把各课串成一张图：笑い 是四层楼，涙 是差分表（一场戏的 6 句 × 5 个轴，越到最后亮得越多）。

### 3.3 用真数据让装置有分量

- 能数的就数出来，从字幕里核对：涙 的「ベアトリス様 ×15 → ベティー ×1」比任何形容词都有力。
- 核对的时候注意坑：贝雅特丽丝的自称也是「ベティー」，计数只能算莉由斯说的那几次。**数字不能编**；没核对完就在画布上写占位，说明还缺什么。
- 场景优先用两部番的原台词，并挑有原声的（Re:ゼロ 26–50 话）。说话人核对过才写名字，拿不准写「有人」。

### 3.4 局部图形按每个知识点自己的形状挑

主装置定了之后，每课揭晓时可以配一个小图。小图的形状要来自这个知识点本身：

| 知识点 | 它本来的形状 | 画法 |
|---|---|---|
| 称呼的升级 | 台阶 | 様 / さん / ちゃん / 呼び捨て / 昵称 一级一级，用一道曲线表示「一次跳三级」 |
| 敬体塌成常体 | 上下两层 | 敬体一层、常体一层，句子在 です 掉下去的那一拍落层 |
| 多年以后兑现的约定 | 时间上的跨度 | 一道很长的弧，从「いつか―」落到「愛している」 |
| 道别 | 关系还往不往下走 | 三种线尾：接着走（虚线）、被剪断（×）、封口（竖杠） |
| 笑点 | 偏离和回归 | 一根线偏出去、折回来 |
| 谐音梗 | 一个音分两条路 | 拍格 + 两道弧 |

旧图形（线、弧、阶梯、楼层）可以用，前提是这个知识点真是那个形状。**想不出它本来的形状，就别配图**，空着比硬套好。

### 3.5 画布只放样板

- 先画一块总图：一屏说清这本的装置，再列出每课用的是装置的哪种变化。
- 每种新版式画 1–2 屏：作答前一屏、揭晓后一屏。**不要把每课都铺上去**（第九巻那次铺了一百多课，被叫停）。
- 便签写四样：界面规则（给写代码的人看）、目次（每课翻哪个轴）、用到的原作场景（标原声 ★）、原文讲错的地方。
- 用户不在手机上看，画布就是方案。画面要接近真机：390 宽、真台词、真罗马音、真中文。

## 4. 不要做的

- **照着现有代码描界面**：那是记录现状，不是设计。
- **把上一本被认可的视觉语言整套搬过来**：每本书的共同结构不一样，装置也应该不一样。
- **画成静态图解**：一张示意图配一段话。用户没有可点的地方，也就不会被吸引。
- **套组件库的素材**：Avatar、SpeechBubble、`speechLines` 之类；也不要默认漫画风。
- **为了「大胆」推翻 App 的结构**（今日页那次改成上划流，被说「还不如上一版」）。创新只在这本书的界面里做。
- **一屏塞几个焦点**：每屏只有一个墨色主按钮，揭晓后亮起来的也只有一处。
- **编数字、编说话人、编剧情**。
- **不写解释性小字**（CLAUDE.md 第 4 节）：讲解只在揭晓后出现，一两句。

## 5. 画完自查（拿给用户看之前逐条过一遍）

1. 能不能用一句话说出这本书的共同结构？画布总图第一眼看到的是不是它？
2. 每一屏的焦点在哪？遮住讲解文字，只看图形，还能不能看出该点哪、点完发生了什么？
3. 用户要动手做什么？是点、选，还是对照？还是只能读？
4. 揭晓画面是不是装置本身的变化（亮、连、移、叠），而不是多出一段文字？
5. 最后一课有没有把各课串起来？
6. 每个局部小图，形状是不是这个知识点本来的形状？有没有哪个是从上一本搬来硬套的？
7. 数字、说话人、场景都核对过吗？有原声的标了吗？
8. 颜色只用了令牌那几种（墨、作品色、info 蓝、ok 绿、bad 红、灰）吗？浅色和深色都想过吗？
9. 便签齐了吗：界面规则、目次、场景、原文错处？

## 6. 从画布到代码

- 画布认可之后，代码照画布实现，小偏差自己定，在汇报里一句带过。
- 新装置写成独立的 Composable 文件（`screens/katsuyou/WaraiLine.kt` 这种，按书命名），用 Compose `Canvas` 自己画，只用 `AjlTheme` 令牌。
- 数据字段都给默认值，旧书的 asset 不能变：改之前备份 `kyoka_books.json`，改完逐本比对。
- 动效走 `MOTION_SPEC.md`，照顾 reduced motion。
